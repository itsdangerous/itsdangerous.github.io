이 글은 블로그 글을 작성할 때 자주 사용하는 Markdown 문법을 한곳에 모아둔 내부 초안입니다. 콘텐츠는 단순한 문법 설명에 그치지 않고, 실제 글에서 어떤 요소를 선택하면 좋은지도 함께 기록합니다.

## 본문을 먼저 쓰기

짧은 설명과 문단은 별도의 박스 없이 본문 위에 놓입니다. 독자가 맥락을 이해하는 데 필요한 내용은 일반 문단으로 쓰고, 특별히 강조해야 하는 내용만 아래의 표면 요소로 분리하는 편이 읽기 좋습니다.

## 인용문으로 문장 강조하기

> 좋은 기록은 내용을 보관하는 동시에, 다시 읽을 수 있는 표면을 만듭니다.

인용문은 책이나 문서에서 가져온 문장을 강조하거나, 글의 핵심 문장을 별도로 남길 때 사용합니다.

## 콜아웃으로 맥락 보충하기

:::note
본문을 읽는 데 도움이 되는 참고 내용을 덧붙일 때 사용합니다.
:::

:::tip
작성 팁이나 더 간단한 방법을 제안할 때 사용합니다.
:::

:::warning
실수하기 쉬운 부분이나 적용 전에 확인해야 할 조건을 알릴 때 사용합니다.
:::

:::success
작업을 완료했거나 정상 동작을 확인한 결과를 남길 때 사용합니다.
:::

:::important
놓치면 안 되는 결정이나 핵심 원칙을 강조할 때 사용합니다.
:::

## 표로 값을 비교하기

| 문법 | 적합한 상황 | 예시 |
| --- | --- | --- |
| 표 | 여러 값을 나란히 비교할 때 | 옵션별 차이 정리 |
| 코드 | 명령어 또는 실행 가능한 예시를 보여줄 때 | `npm run build` |
| 인용문 | 다른 문장의 의미를 강조할 때 | 책, 문서, 인터뷰 인용 |
| 콜아웃 | 본문 흐름을 유지하면서 주의사항을 덧붙일 때 | 참고, 팁, 경고 |

열이 많아지면 표가 가로로 스크롤될 수 있으므로, 각 셀의 문장은 가능한 한 짧게 유지합니다.

## 코드 블록으로 명령어 남기기

```zsh
git status --short
npm run test -- --run
npm run build
```

언어 식별자를 붙이면 코드 패널의 문맥을 분명하게 전달할 수 있습니다. 예를 들어 셸 명령어에는 `zsh` 또는 `bash`, Python 예제에는 `python`을 사용할 수 있습니다.

## 목록으로 순서와 조건 정리하기

- 글의 목적과 대상 독자를 먼저 정합니다.
- 핵심 내용을 일반 문단으로 설명합니다.
- 필요한 경우에만 표, 코드, 인용문, 콜아웃을 추가합니다.
  - 한 단계 안쪽의 목록은 세부 조건을 설명할 때 사용합니다.

## 작성 원칙

표면 요소는 장식만을 위해 사용하기보다 정보의 역할에 맞춰 선택합니다. 본문은 문맥을 담당하고, 표는 비교를, 코드는 재현 가능한 절차를, 인용문은 강조를, 콜아웃은 보충 설명을 담당하도록 구분하면 긴 글도 구조가 분명해집니다.
